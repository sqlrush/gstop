# gstop v1.6.2 Schema-Qualified Plan Diagnosis Design

## Context

Scenario 601 runs a schema-qualified point lookup. After its lookup index is
dropped, openGauss reports a current `Seq Scan on plan_data` without a schema.
The test database contains the same table name in three schemas, so gstop's
bare-name catalog lookup becomes ambiguous even though the full SQL names the
target schema. Baseline `ANALYZE` statements also expose intentional maintenance
scans that must not be treated as missing-index candidates.

## Design

- Prefer safe verbose EXPLAIN so current plans carry schema-qualified relation
  evidence, with the existing safe EXPLAIN as a compatibility fallback.
- Enrich unresolved plan accesses from lexically parsed, schema-qualified table
  references in the full SQL. Bind only one provable match; never guess across
  multiple same-name references, comments, literals, or ambiguous aliases.
- Pass the SQL evidence associated with the selected catalog plan into catalog
  diagnosis. Keep historical plans for display and current plan/catalog evidence
  for diagnosis.
- Mark `ANALYZE` and `VACUUM` index advice as not applicable and never generate
  CREATE INDEX candidates for their maintenance scans.
- Preserve catalog failure handling, cancellation, and stale asynchronous-result
  guards.

## Acceptance

- Regression coverage includes three same-name schemas, ambiguous multi-schema
  SQL, quoted identifiers/comments/literals, verbose fallback, maintenance
  statements, and existing plan-source concurrency behavior.
- `go test ./... -count=1`, `go vet ./...`, and focused detail-pipeline race tests
  pass.
- A real og5 601 restore/init/fault/recover cycle proves SQL ID 3877360001 is
  diagnosed against `gsbench_e2e_20260801_100g.plan_data`, reports the dropped
  index, produces a `lookup_key` candidate, and returns to Index Scan after
  recovery without database-memory or connection errors.
- Ship and locally deploy gstop v1.6.2 by replacing only `gstop.real`, preserving
  the wrapper, configuration, environment file, and a v1.6.1 backup.
